## 它是什么

**薪连薪合规助手（XinLianXin Helper）** 是北京薪连薪科技有限公司推出的 AI Agent Skill（智能体技能包）。

它面向企业、平台、园区和生态服务商，将公开法规、通用业务分析方法和结构化合规检查规则封装为可由兼容 Agent 调用的 Skill，帮助用户对灵活用工与平台经济相关场景进行：

- 业务事实梳理
- 模式适配判断
- 资料与证据缺口检查
- 平台涉税关注点梳理
- 园区准入评估
- 初步风险提示
- 下一步真实业务动作建议

它的目标不是替用户直接下“合规 / 不合规”结论，而是先把复杂问题拆开，区分：

```text
已知事实
待确认事项
资料缺口
风险关注点
下一步动作
应留存的真实证据
```

> **重要说明**  
> 本 Skill 提供的是初步合规信息整理与风险提示，不构成法律、税务、审计、劳动关系或监管意见，也不出具任何“合规证明”“无风险证明”或监管认可结论。

## 核心能力

### 1. 合作模式与适配判断

根据用户提供的真实、脱敏业务事实，帮助梳理：

- 业务目的
- 人员关系
- 管理方式
- 任务与交付方式
- 结算依据
- 平台或园区角色

在信息足够时给出初步判断，例如：

```text
更适合当前模式
需要优化后再判断
风险较高
信息不足，暂不能判断
```

不会在事实不足时强行下结论。

---

### 2. 灵活用工场景初步分析

适用于：

- 兼职
- 众包
- 推广
- 佣金结算
- 项目制任务
- 平台任务
- 园区服务
- 其他灵活协作场景

重点不是只看“有没有合同、有没有付款”，而是检查真实业务是否能够被说明、留痕和复核。

---

### 3. 资料与证据缺口检查

围绕真实业务检查：

- 协议
- 任务
- 订单
- 过程记录
- 验收
- 支付
- 票据
- 申报
- 其他关键资料

输出时区分：

```text
已有资料
缺失资料
待确认事实
潜在风险
下一步真实动作
建议留存的真实证据
```

本 Skill 不建议倒签、补造、虚构历史业务资料。

---

### 4. 平台涉税关注点梳理

可对平台经济相关的公开法规和政策要求进行结构化说明，帮助用户理解：

- 哪些事项需要关注
- 哪些义务与平台角色有关
- 哪些内容需要进一步核实
- 哪些问题需要转人工税务或法律专业人员处理

政策类回答会尽量区分：

```text
已施行
将施行
待核实信息
媒体叙事
```

涉及法规时，优先使用可核验的正式文号和公开来源。

---

### 5. 园区准入评估

可辅助园区或平台梳理：

- 企业基本情况
- 业务场景
- 资料完整度
- 主要风险项
- 待补充材料
- 是否需要进一步人工复核

用于形成结构化的准入参考，不替代园区、平台或专业机构的正式审核。

---

### 6. 企业合规报告咨询引导

当用户需要进一步进行企业合规体检、人工深度评估或正式咨询时，Skill 可以帮助用户先整理：

- 当前业务类型
- 主要问题
- 已有资料
- 缺失资料
- 需要进一步确认的事实
- 建议脱敏后提供的信息

不会承诺必然出具报告、固定价格、固定时效或监管结果。

---

### 7. 高风险请求识别

对于以下请求，Skill 会拒绝提供违规路径：

- 将事实劳动关系包装为灵活用工
- 倒签、补造或虚构业务资料
- 设计资金回流
- 虚开发票
- 阴阳合同
- 虚构成本
- 规避法定报送义务
- 要求出具“合规证明”“无风险证明”

拒绝后仍可提供基于真实业务的合规替代方向。

## 它如何工作

```text
用户当前使用的 Agent
        ↓
读取 xinlianxin-helper Skill 指令
        ↓
按需读取 references/
        ↓
调用用户当前 Agent 所使用的模型进行推理
        ↓
输出结构化分析结果
```

### 不需要单独配置薪连薪大模型 API

本 Skill 本身**不提供独立大模型服务**。

模型推理、上下文长度和 Token 消耗取决于用户当前使用的 Agent 环境。

### 客户对话不会主动调用外部 API

当前 Skill 的客户对话流程以提示词、规则和本地参考资料为主，不要求在每次分析时调用薪连薪服务器。

包内可能包含的维护或回归脚本，仅用于开发维护和版本自测，不作为普通客户会话功能。

## 输出原则

### 结论先行

先回答当前能确认到什么程度，再展开说明。

### 事实和待确认事项分开

不会把用户没有提供的信息自动当成事实。

### 信息不足时优先追问关键问题

通常只追问少量真正影响判断的事实，避免重复盘问。

### 建议必须对应真实动作

建议尽量采用：

```text
资料缺口
→ 下一步真实业务动作
→ 应留存的真实证据
```

而不是只输出抽象的“加强合规管理”。

### 不制造历史事实

对于已经发生的业务：

- 可以依据用户真实事实整理现有记录
- 可以指出缺少什么
- 可以提出未来如何改进

但不会生成看起来像历史同期已经形成的虚假资料。

## 安全边界

### 不替代专业意见

输出仅用于初步信息整理和风险提示，不构成：

- 法律意见
- 税务鉴证
- 审计意见
- 劳动关系认定
- 行政或监管认定

### 不做规避设计

不会协助：

- 规避法定义务
- 资金回流
- 虚开发票
- 阴阳合同
- 虚构成本
- 隐瞒真实劳动关系
- 其他违法违规安排

### 不补造历史资料

可以说明未来真实业务应如何留存资料，但不会建议：

- 倒签
- 补签并伪装历史形成时间
- 伪造任务
- 伪造验收
- 伪造业务过程
- 伪造合同或凭证

### 不出具“合规证明”

Skill 的分析结果不是：

```text
合规认证
监管认可
免责依据
法律意见书
税务鉴证报告
```

## 隐私原则

使用 Skill 时，建议先对业务材料进行脱敏。

通常**不需要**提供：

- 身份证号
- 银行卡号
- 账户密码
- 完整个人住址
- 完整订单号
- 未脱敏合同
- 与当前分析无关的大量个人名单

推荐只提供完成初步判断所需要的最少信息。

## Skill 包结构

当前 Skill 以 `SKILL.md` 为主入口。

典型结构：

```text
xinlianxin-helper/
├── SKILL.md
├── .skill-metadata.yaml
├── references/
│   └── ...
└── tools/
    └── run_regression.py
```

### `SKILL.md`

Skill 的主入口文件，包含：

- 触发条件
- 分析规则
- 回答结构
- 安全边界
- 引用和时效要求

### `.skill-metadata.yaml`

用于保存版本、名称等 Skill 元数据。

### `references/`

保存 Skill 使用的参考资料、规则说明和受控知识内容。

### `tools/run_regression.py`

用于维护侧回归测试。

普通用户通常不需要直接运行该脚本。

## 使用示例

### 场景分析

**输入：**

> 我们有一批兼职销售按成交佣金结算，帮我判断这个场景还需要核对哪些事实和资料。

Skill 会优先梳理：

- 人员管理方式
- 是否可自主接单
- 实际任务
- 交付和验收
- 结算依据
- 已有资料
- 待确认事实

### 资料自查

**输入：**

> 我们已经有协议、任务记录和支付凭证，但验收资料不完整，帮我做一次资料缺口自查。

Skill 会区分：

```text
已经存在的资料
仍然缺失的资料
不能从现有资料推断的事实
下一步真实业务应如何补强
```

### 平台涉税问题

**输入：**

> 我们是平台企业，平台涉税信息报送和相关申报义务分别需要关注什么？

Skill 会先识别平台角色、业务情况和当前问题，再结合受控法规基线做结构化说明。

### 模式适配

**输入：**

> 我们是产业园区，希望建设平台经济服务能力，现有几种合作方式里更接近哪一种？

Skill 会先确认园区实际业务、服务对象、平台能力和运营方式，再做初步适配分析。

### 深度评估准备

**输入：**

> 我们希望申请企业合规报告咨询，需要先准备哪些脱敏信息？

Skill 会先帮助整理问题和资料范围，减少后续人工沟通中的信息缺失。

## 回归测试

当前 Skill 维护流程包含回归测试机制。

测试重点包括：

- 高风险请求拒绝
- 法规时效
- 信息不足处理
- 隐私提醒
- 极限施压场景
- 结构化输出
- 版本更新后的关键行为一致性

当前版本的维护基线包含 **25 题回归测试**。

> 回归测试用于降低版本修改引入行为偏差的风险，不代表“准确率 100%”，也不构成对任何具体业务结果的保证。

## 法规与时效

Skill 可能引用与平台经济、灵活用工和涉税信息相关的公开法规与政策。

政策类回答遵循以下原则：

```text
优先正式文号
优先官方来源
区分发布日期与施行日期
区分已施行与将施行
不把媒体消息直接当成现行法规
无法核验的政策传言不直接确认
```

由于法规、政策和监管口径可能更新，使用时应以最新正式文件和主管机关公开信息为准。
